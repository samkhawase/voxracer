## Project rules

- Read relevant source, tests, and documentation before editing.
- Keep the core provider-neutral.
- Treat unknown measurements as unknown. Never replace them with zero.
- Do not add provider data, prompts, transcripts, phone numbers, or credentials
  to fixtures, logs, examples, or documentation.
- Add or update tests with every behavior change.
- Run focused tests and the full test suite before reporting completion.
- Do not change the public schema without updating its documentation and tests.
- Do not create commits unless the user asks for them.
- Use `apply_patch` for file edits.
